# Pulsa API

REST API for **Pulsa — Your Personal Heart Coach**: cardio coaching (heart metrics,
daily adaptive plan, programs, coaches, pricing, contact, newsletter) plus the
original My-Fitness gym-admin features (members / membership cards, staff,
activity).

- **Stack:** Node 20 · Express 5 · TypeScript · MongoDB (Mongoose) · zod · JWT + bcrypt
- **Security:** helmet, CORS allow-list from env, per-IP rate limits, rotating refresh tokens
- **Contract:** [`../docs/API.md`](../docs/API.md) · OpenAPI at `GET /api/v1/openapi.json`

## Run locally

You need Node 20+ and a MongoDB (local `mongod`, Docker, or a free MongoDB Atlas cluster).

```bash
cd backend
cp .env.example .env        # then edit MONGODB_URI and JWT_SECRET
npm install
npm run seed                # wipes the DB and loads demo data
npm run dev                 # http://localhost:4000/api/v1/health
```

### Demo accounts (after `npm run seed`)

| Role   | Email                 | Password |
|--------|-----------------------|----------|
| member | `demo@pulsa.example`  | `SEED_DEMO_PASSWORD` (default `pulsa-demo-2026`) |
| coach  | `coach@pulsa.example` | `SEED_COACH_PASSWORD` — if empty, the seed prints a random one (never the demo password: coaches can read their clients' data) |
| admin  | `SEED_ADMIN_EMAIL` (default `admin@pulsa.example`) | `SEED_ADMIN_PASSWORD` — if empty, the seed prints a random one |
| demo admin (read-only) | `demo-admin@pulsa.example` | `pulsa-demo-admin` (public on purpose) |

The **demo admin** is the public login behind the "Demo admin" button (the portfolio embeds it). It has the
admin role but `isDemo: true`: the API answers every write with `403 DEMO_READ_ONLY` and hides lists with
visitors' personal data (`/users`, `/contact`, `/newsletter`, other users' metrics). `npm run seed:demo-admin`
(or `seed:demo-admin:prod` after a build) adds or resets only this account, without wiping anything.

The demo member has 90 days of heart data (30 days with a full heart-rate series);
today's numbers match the landing page hero: **72 bpm, 24k steps, 1.32 recovery**.

## Scripts

| Script | What it does |
|---|---|
| `npm run dev` | watch mode with `tsx` |
| `npm run build` | compile to `dist/` |
| `npm start` | run `dist/server.js` |
| `npm run seed` | wipe + seed (dev, TypeScript) |
| `npm run seed:demo-admin` / `seed:demo-admin:prod` | add or reset only the read-only demo admin (no wipe) |
| `npm run seed:prod -- --force` | wipe + seed from `dist/` (`--force` and `SEED_DEMO_PASSWORD` are required when `NODE_ENV=production`) |
| `npm test` | supertest + vitest against an in-memory MongoDB (set `MONGO_TEST_URI` to use a real one) |
| `npm run typecheck` | `tsc --noEmit` |

Tests run one file at a time (low-RAM friendly). The first run downloads a
MongoDB binary for `mongodb-memory-server` (cached afterwards).

## Environment

See [`.env.example`](.env.example).

| Variable | Required | Default | Notes |
|---|---|---|---|
| `MONGODB_URI` | yes | `mongodb://127.0.0.1:27017/pulsa` | Atlas: `mongodb+srv://USER:PASS@cluster.xxxx.mongodb.net/pulsa?retryWrites=true&w=majority` |
| `JWT_SECRET` | yes in production | dev-only fallback | ≥ 32 random chars; server refuses to start in production without it |
| `CORS_ORIGINS` | yes | `http://localhost:3000` | comma-separated frontend origins |
| `PORT` | no | `4000` | Render sets this automatically |
| `JWT_ACCESS_TTL` | no | `900` | seconds |
| `JWT_REFRESH_TTL_DAYS` | no | `30` | |
| `TRUST_PROXY` | no | `1` | proxy hops (for correct client IPs in rate limiting) |
| `RATE_LIMIT_ENABLED` | no | `true` | |
| `PUBLIC_MEMBER_BASE` | no | `12400` | marketing offset for `/stats/public`; `0` = real count |
| `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` / `SEED_COACH_PASSWORD` / `SEED_DEMO_PASSWORD` | seed only | | admin and coach passwords are random (printed once) if empty; demo defaults to `pulsa-demo-2026` in dev only |

## Deploy to Render (free)

`render.yaml` at the repo root is a Render Blueprint (web service, `rootDir: backend`).

1. Create a free **MongoDB Atlas** M0 cluster → Database Access: add a user →
   Network Access: allow `0.0.0.0/0` (Render free has no static IP) → copy the
   connection string and add the database name (`/pulsa`).
2. Render → **New → Blueprint** → select this repo → it reads `render.yaml`.
3. When asked, paste `MONGODB_URI`. `JWT_SECRET` is generated by Render.
   Adjust `CORS_ORIGINS` if the frontend URL differs.
4. After the first deploy, seed once from your machine against Atlas:
   ```bash
   cd backend && npm run build
   MONGODB_URI="<atlas uri>" NODE_ENV=production SEED_ADMIN_PASSWORD="<strong>" SEED_COACH_PASSWORD="<strong>" SEED_DEMO_PASSWORD="<demo>" JWT_SECRET="<any 32+ chars>" npm run seed:prod -- --force
   ```
5. Check `https://<service>.onrender.com/api/v1/health` → `{"data":{"status":"ok","db":"up"}}`.
6. In the frontend (Vercel) set `NEXT_PUBLIC_API_URL=https://<service>.onrender.com/api/v1`.

Free Render services sleep after ~15 min idle; the first request then takes ~30–60 s.

## Layout

```
src/
  app.ts            express app (helmet, cors, rate limits, routers, errors)
  server.ts         connect DB + listen + graceful shutdown
  config.ts         env parsing (zod)
  openapi.ts        OpenAPI 3.1 document
  lib/              errors, validation, pagination, dates, slug
  middleware/       auth (JWT, roles), error handler, rate limits
  models/           Mongoose schemas
  routes/           auth, users, programs, coaches, pricing, metrics, plan,
                    contact+newsletter, stats, gym (members, staff, admin)
  services/         tokens, metric aggregations, rule-based daily plan
  seed/             demo data + seed script
tests/              vitest + supertest suites
```
